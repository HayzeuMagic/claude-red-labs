PART B — FULL INSTALLATION PROCEDURE, FROM A FRESH WINDOWS PC
================================================================================
This section is self-contained: a beginner can follow it top to bottom without
having read Part A. It applies to BOTH kinds of PC (dev PC with Hyper-V, target
deployment PC without) except where a step says otherwise. Step numbers match
docs/02-offline-installation.md's step numbers — follow this section for the
condensed command sequence, that doc for the longer explanation of each step.

Before you start, know this:
- Two terminal types exist on Windows: Windows PowerShell and Command Prompt
  (CMD). They are NOT interchangeable for setting environment variables or
  activating a Python virtual environment. Every command block below says which
  one to use.
- "Normal User" means: do not right-click "Run as Administrator" to open the
  terminal. "Administrator" means you do need to right-click and choose that —
  this procedure needs Administrator for exactly zero steps on a target
  deployment PC when the default port works, which it should on a PC without
  Hyper-V.
- To open PowerShell: press the Windows key, type "PowerShell", press Enter.
- To change directory: `cd C:\path\you\want` (PowerShell and CMD both accept this).
- A failed command shows red text and/or the word "Error". A successful one
  does not. If you're not sure, re-read the "Expected result" line under that
  step before moving on.

ONLINE PREPARATION (needs internet access)

STEP 1 — Check what's already installed
  Purpose: avoid reinstalling software that already works.
  Terminal: Windows PowerShell — Normal User
  Privileges: Normal User
  Working directory: any (e.g. your home folder)
  Commands (run one at a time, read the output of each before the next):
    git --version
    python --version
    docker --version
    ollama --version
  Expected result: each prints a version number with no "is not recognized" error.
  Verification: literally the output appearing without an error.
  Troubleshooting:
    - "is not recognized as the name of a command": that program is not installed,
      or was installed before this terminal was opened (close and reopen the
      terminal first, since installers update PATH only for new terminals).
    - If still missing after reopening: install it (see Step 1a-1d below) then
      reopen the terminal again.

STEP 1a — Install Git (only if missing)
  Terminal: Windows PowerShell — Normal User
  Download: https://git-scm.com/downloads — run the installer, accept defaults,
  reopen your terminal afterward.

STEP 1b — Install Python (only if missing, or if `python --version` shows < 3.9)
  Terminal: Windows PowerShell — Normal User
  Download: https://www.python.org/downloads/ — during install, check the box
  "Add python.exe to PATH". Reopen your terminal afterward.
  Note: this kit's Lab 2 app (Flask 3.0.3) was confirmed to install and run
  correctly on Python 3.14.3 in this session — you do not need an older Python.

STEP 1c — Install Docker Desktop (only if missing; needed for Lab 1 only)
  Terminal: Windows PowerShell — Normal User (the installer itself will prompt
  for Administrator automatically — that's expected and fine)
  Download: https://www.docker.com/products/docker-desktop/
  After installing, open "Docker Desktop" from the Start menu once and leave it
  running — `docker` commands only work while its background service is up.
  Verify:
    docker info
  Expected result: prints server details ending in something like
  "ServerVersion: 29.x.x" / "OSType: linux" with no connection error. If you see
  "failed to connect to the docker API at npipe:////./pipe/dockerDesktopLinuxEngine",
  Docker Desktop's backend hasn't finished starting yet — open the Docker Desktop
  app from the Start menu (or `Start-Process "C:\Program Files\Docker\Docker\Docker Desktop.exe"`)
  and wait about 30-60 seconds, then retry `docker info`.

STEP 1d — Install Ollama (only if missing)
  Terminal: Windows PowerShell — Normal User (per-user install, no Administrator needed)
  Command:
    irm https://ollama.com/install.ps1 | iex
  Or download OllamaSetup.exe from https://ollama.com/download and run it.
  Verify the CLI:
    ollama --version
  Expected result: "ollama version 0.x.x" (this record was validated against 0.40.9).

STEP 2 — Confirm the Ollama server itself is reachable
  Terminal: Windows PowerShell — Normal User
  Privileges: Normal User
  Working directory: any
  Commands (one at a time):
    Get-Process | Where-Object { $_.Name -like "*ollama*" }
    Invoke-RestMethod http://127.0.0.1:11434/api/tags
  Expected result: the first shows at least one process; the second returns a
  JSON object with a "models" key (an empty list is fine the first time).
  Verification: no red error text from either command.
  Troubleshooting (read this before trying anything else):
    If you see "Error: timed out waiting for server to start",
    "Warning: could not connect to a running Ollama instance", or
    "listen tcp 127.0.0.1:11434: bind: An attempt was made to access a socket in
    a way forbidden by its access permissions" — STOP and work through
    docs/07-ollama-windows-troubleshooting.md in the repository rather than
    retrying the same command. Short version of what that doc has you check, in
    order, all read-only and needing no Administrator rights:
      1. Get-Process | Where-Object { $_.Name -like "*ollama*" }   (is it already running?)
      2. Get-NetTCPConnection -LocalPort 11434 -ErrorAction SilentlyContinue
         (is something else listening?)
      3. netsh interface ipv4 show excludedportrange protocol=tcp
         (is 11434 inside a Windows-excluded range? — an empty result from #2 does
         NOT mean the port is usable if #3 shows it excluded)
      4. Only if 11434 is confirmed excluded or occupied: pick a DIFFERENT port
         (confirmed free in BOTH checks #2 and #3 for that new port number — do
         not just guess one), then set it identically in every terminal you use
         for Ollama:
           PowerShell:  $env:OLLAMA_HOST = "127.0.0.1:<port>"
           CMD:         set OLLAMA_HOST=127.0.0.1:<port>
         These are not interchangeable syntax — use the one matching your shell.
         Re-verify with: Invoke-RestMethod http://127.0.0.1:<port>/api/tags
    On the dev PC used to write this record, 11434 (and 11500) were confirmed
    excluded by Windows, and port 20000 was confirmed free and working, but THAT
    IS NOT A UNIVERSAL DEFAULT — check your own machine with the steps above
    rather than assuming port 20000. On a target deployment PC without Hyper-V,
    11434 is expected to work out of the box; only fall back to an alternate
    port if you've actually confirmed 11434 is blocked on that specific machine.
